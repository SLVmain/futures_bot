## Выполненные изменения

### 1. Корректировка TP на два ценовых пункта

Коммит: `3204532 Adjust take profits by two price ticks`.

Для новых сделок тейк-профиты сдвигаются на два минимальных шага цены
инструмента Bitunix:

- LONG — на два пункта ниже значения из сигнала;
- SHORT — на два пункта выше значения из сигнала.

Пример при минимальном шаге `0.00001`:

```text
Сигнал:   0.59730
LONG TP:  0.59728
SHORT TP: 0.59732
```

Размер пункта определяется по `quote_precision` конкретной торговой пары,
а не задаётся фиксированным числом для всех инструментов.

Основные файлы:

- `config/settings.py`;
- `services/trade_planner.py`;
- `tests/unit/test_trade_planner.py`;
- `tests/unit/test_trade_service.py`.

### 2. Объединение Telegram-уведомлений и чистый PnL

Коммит: `11e9685 Consolidate trading notifications`.

Одна сделка технически разбивается на несколько защищённых входных ордеров —
по одному на каждый TP. Теперь их WebSocket-события объединяются по общему
префиксу `clientId`.

Бот:

- суммирует исполненный объём частей входа;
- рассчитывает средневзвешенную цену;
- суммирует комиссии входа;
- отправляет одно уведомление вместо сообщения для каждой части;
- подавляет дублирующие события `Позиция открыта` для этой бот-сделки;
- объединяет успешные проверки нескольких TP;
- не скрывает ошибки отдельных частей;
- показывает ручное или неизвестное исполнение нейтрально как исполненный
  ордер, не называя его входом бота.

При закрытии позиции Telegram показывает:

- реализованный PnL;
- комиссию;
- funding;
- чистый результат.

Формула совпадает с итоговой записью CSV:

```text
net PnL = realizedPNL + funding - abs(fee)
```

Если Bitunix не передал одно из необходимых значений, бот показывает
`нет данных` и не рассчитывает недостоверный чистый результат.

Основные файлы:

- `services/position_monitor.py`;
- `tests/unit/test_position_monitor.py`.

### 3. Автоматический fee-aware безубыток после TP1

Коммит: `0184739 Automate break-even stop after TP1`.

Добавлен явный параметр:

```dotenv
AUTO_MOVE_STOP_LOSS_ON_TP1=true
```

Поведение:

- `true` — после подтверждённого WebSocket-события исполнения TP1 бот
  автоматически переносит SL всех оставшихся частей этой сделки в fee-aware
  безубыток;
- `false` — сохраняется прежняя кнопка подтверждения в Telegram;
- значение по умолчанию — `true`;
- команда `/mode` показывает активный вариант;
- при ошибке переноса бот сообщает, что позиции и SL нужно проверить на
  Bitunix.

Расчёт учитывает накопленную комиссию позиции, отрицательный funding и
предполагаемую taker-комиссию закрытия. Источником события TP1 остаётся
приватный WebSocket Bitunix, а не текстовое сообщение автора сигнала.

На другой машине параметр желательно явно добавить в локальный `.env`:

```dotenv
AUTO_MOVE_STOP_LOSS_ON_TP1=true
```

Сам `.env` нельзя читать, выводить или коммитить.

## 4. Сопровождение сигналов и ручные расчёты

Коммит: `608e563 Handle signal lifecycle updates`.

Добавлено распознавание сообщений сопровождения:

- `идея закрыта в безубытке`;
- `отмена, цена ушла`;
- `идея закрывается по стопу`;
- `достигнута первая цель`;
- `закрываю идею по текущим ценам`;
- `закрыто из-за противоположной сделки`.

Суффикс TradingView `.P` удаляется, а короткий символ вроде `#XRP`
нормализуется в `XRPUSDT`. Цена закрытия и процент из сообщения сохраняются
как данные автора, но фактическое состояние и PnL берутся с Bitunix.

Матрица поведения:

| Событие | Предложение |
|---|---|
| `идея закрыта в безубытке` | Отменить все входы и закрыть все позиции по символу |
| `отмена, цена ушла` | Отменить все входы и закрыть все позиции по символу |
| `идея закрывается по стопу` | Отменить все входы и закрыть все позиции по символу |
| `закрываю по текущим ценам` | Отменить все входы и закрыть все позиции по символу |
| `закрыто из-за противоположной сделки` | Отменить все входы и закрыть все позиции по символу |
| `достигнута первая цель` | Только информация; действие запускает WebSocket Bitunix |

Отмена и закрытие требуют Telegram-подтверждения. Непосредственно перед
выполнением повторно проверяются символ и точные ID. Сначала отменяются
ожидающие входы, затем закрываются позиции. Если Bitunix отклонил хотя бы одну
отмену, закрытие останавливается, чтобы оставшийся ордер не открыл позицию
повторно.

По явному решению пользователя все позиции и обычные входные ордера по
символу, включая созданные вручную, предлагаются для действия. Несколько
позиций перечисляются отдельно. `reduceOnly`-ордера не считаются входами.

Сообщение о TP1 не переносит SL по тексту автора. Фактическое исполнение
подтверждает приватный WebSocket Bitunix, после чего применяется
`AUTO_MOVE_STOP_LOSS_ON_TP1` и выполняется fee-aware перенос.

Дополнительные сценарии:

- если нет ни позиций, ни ордеров, выводится информационное сообщение и
  никакое действие не создаётся;
- ошибка API не трактуется как отсутствие сделки;
- одинаковый текст в течение десяти минут не создаёт второе действие;
- фото без подписи игнорируется и не очищает контекст;
- подпись к фото или следующий отдельный текст обрабатываются самостоятельно;
- результат каждого этапа сохраняется в CSV со статусами `RECEIVED`,
  `NO_ACTIVE_TRADE`, `ACTION_COMPLETED`, `ACTION_PARTIAL` и другими.

Для инструмента с `isApiSupported=false` расчёт по доступным данным Bitunix
всё равно выполняется: показываются объём по риску, вход, TP, SL и ожидаемый
результат. Экран помечается как `РУЧНОЕ РАЗМЕЩЕНИЕ`, торговое предложение не
сохраняется, кнопка автоматического входа отсутствует, а исполнитель
дополнительно блокирует отправку такого плана через API. Если Bitunix не
возвращает цену, точность или торговые лимиты, бот не подставляет вымышленные
значения и расчёт не выполняет.

# Дополнение: локальные триггеры входа

- Опасный LIMIT (LONG выше текущей цены или SHORT ниже текущей цены) теперь
  превращается в `TRIGGER_MARKET`, а не отправляется на биржу сразу.
- Состояние хранится в `data/emulated_triggers.json` и исключено из Git.
- Пока бот работает, цена проверяется через публичный REST Bitunix. После
  достижения триггера отправляется MARKET-пакет с уже прикреплёнными TP/SL.
- Перед отправкой повторно проверяется отсутствие позиции и ордера по символу.
- После остановки, перезапуска или потери цены триггер становится
  `SUSPENDED`; поздний автоматический вход запрещён.
- При запуске Telegram показывает исходный диапазон, условие, последнюю и
  текущую цены, TP/SL и кнопки повторной активации, пересчёта либо отмены.
- Настройки: `ENABLE_EMULATED_ENTRY_TRIGGERS`, `TRIGGER_POLL_SECONDS`,
  `TRIGGER_MAX_AGE_MINUTES`, `TRIGGER_STATE_PATH`.
- Тесты после изменения: `200 passed`.
